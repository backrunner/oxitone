# 工程化与模块边界

适用于手写 TypeScript、Rust、UI、脚本和测试。新增功能与重构遵循相同标准。

## 文件与职责

- 一份文件负责一个可命名的职责。目标 150–250 行；接近 300 行时拆分，避免继续向大文件
  追加新职责。行数按格式化后的源码计算，不通过压缩表达式、删除合理空行规避。
- 一个函数同时处理多个职责，即使文件较短，也应按数据流拆分。布局组合模块只组织子模块，
  不同时承担事件算法、IPC、平台生命周期和绘制细节。
- UI 分为语义主题、通用控件、区域布局、手势状态、坐标/变换算法、绘制与平台适配。
  控件接收明确输入并发出语义动作；源码写回仍经 Document Service，音频所有权不变。
- 按领域和职责命名，例如 `piano_feedback`、`note_transform`、`document_controls`；不使用
  `utils`、`helpers2`、`part1` 等无法解释边界的容器。模块数不是目标，不为几行转发拆文件。
- 默认保持模块私有，只暴露组合层需要的接口。避免循环依赖、跨层修改内部状态，以及为拆分
  新建全局单例或第二份事实来源。Rust 可为同一 UI 类型分职责实现方法，公共协议不能随文件移动改变。

## 测试与例外

- 测试与负责行为的模块对应；大测试文件按场景拆分。纯坐标/变换测试不启动窗口，UI smoke
  验证真实布局和事件通路，音频测试仅使用模拟输出或离线渲染。
- 生成的 binding/schema、静态 golden 数据不受行数目标约束，不手工修改生成文件。
  手写协议声明或不可分割的算法需要超过约 300 行时，在变更记录说明具体原因及边界；
  这是工程判断要求，不额外引入用户批准流程。
- 修改已有超长文件时，优先抽取本次涉及的独立职责；不借机重写无关模块。
- Review 核对格式化后行数、依赖方向、接口可见性及行为是否保持。纯移动不需要重复制造测试，
  运行已有针对性测试；行为变化补回归测试，并完成仓库规定的 lint/typecheck/Rust 检查和基准。

Preview 主题颜色位于 `theme.rs`，控件位于 `ui_controls.rs`；标题栏、原生窗口拖动、传输栏、
文档按钮分别独立。编排/停靠区组合与尺寸算法分离；钢琴窗的工具、反馈、绘制和音符变换分别维护。
